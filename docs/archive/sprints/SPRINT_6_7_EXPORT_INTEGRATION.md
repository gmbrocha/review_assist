# Sprint 6.7: Export Integration

## Status

Parked draft for review. Do not implement until figure versions and approval state exist.

## Purpose

Update report/export figure resolution so exports use approved or regenerated figure versions explicitly.

## Export Priority

When exporting a report:

1. Use approved reviewer version if present.
2. Otherwise use latest regenerated version if no approved version exists.
3. Otherwise use autogenerated version.

The hierarchy may change later, but current behavior must be explicit in code, tests, and manifests.

## Export Requirements

Exports should:

- preserve figure numbering
- preserve captions
- preserve source notes and method notes
- preserve report references
- preserve legend generation from the rendered artifact/metadata
- avoid stale autogenerated versions when an approved reviewer version exists
- record which version was exported
- preserve review-before-export semantics

## Integration Points

Inspect and update the existing figure asset resolver rather than duplicating export logic.

Likely affected areas:

- export manifest generation
- figure asset copying
- Markdown figure references
- DOCX figure embedding
- package manifest figure asset metadata
- compactness/fidelity tests

## Review Gate Interaction

Approval of a figure version should not bypass the standard review gate for the deliverable item unless the existing product decision explicitly maps figure approval to terminal/export-eligible state.

If figure-version approval and review queue item approval remain separate, the UI/export behavior must make that clear.

## Tests

Add or update tests for:

- approved figure version is exported by default
- latest regenerated version is exported when no approved version exists
- autogenerated version is exported when no regenerated version exists
- export manifest records selected figure version
- DOCX/Markdown use the selected version artifact path
- captions and figure numbering remain stable
- stale autogenerated version is not used when approved version exists
- review gate still blocks unreviewed items as before

## Definition Of Done

- Export resolver uses explicit version priority.
- Export/package manifests identify selected figure versions.
- Existing report structure and figure numbering remain stable.
- Review gate semantics remain intact.

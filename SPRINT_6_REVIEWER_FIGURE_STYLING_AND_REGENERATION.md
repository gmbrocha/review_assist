# Sprint 6: Reviewer Figure Styling And Regeneration

## Status

Parked draft for review. Do not implement until the Sprint 6 plan is accepted and the current stabilization/code checkpoint is clean enough to build on.

This file and the linked subunit files are root-level planning notes for human review. They intentionally follow the Sprint 5 root-doc convention.

## Sprint Goal

Implement a constrained reviewer-facing figure editing workflow that allows reviewers to adjust figure presentation and symbology without modifying analytical truth, source geometry, source records, or derived results.

All reviewer edits must be:

- structured
- reproducible
- auditable
- regeneratable from source data, analysis snapshot, figure recipe, and reviewer style overrides

This is not a full GIS editor.

## Change Classification For Implementation

Sprint 6 implementation is a `DOMAIN EXTENSION`.

It adds new modeled concepts: figure recipes, reviewer style overrides, render jobs, figure versions, approval state by version, and export resolution for approved/reviewer-regenerated figure artifacts.

It must not become a `DANGEROUS PATCH`. Any implementation that mutates source data, source geometry, analysis outputs, acreage/intersection metrics, comparison logic, source truth, review gates, or regulatory determinations is outside this sprint and requires explicit approval.

## Core Philosophy

Reviewer edits are presentation overrides.

They improve:

- readability
- communication
- emphasis
- layer clarity
- report usability

Reviewer edits are not:

- source data edits
- geometry edits
- analytical recalculations
- hidden determination overrides
- replacements for GIS analysis

The analytical layer remains immutable.

## Primary Deliverables

### Reviewer Figure Editor UI

Create a lightweight browser-based figure styling/editor panel for generated figures.

The editor should display the current generated figure/map and support:

- current figure preview
- loading state
- regeneration state
- updated preview after style changes are saved/regenerated

Live preview is optional for the first version.

The layer list should expose layers used in the selected figure and provide:

- visibility toggle
- layer ordering
- active layer selection
- layer display name

Initial v1 styling controls:

- fill color
- fill opacity
- stroke color
- stroke width
- point size, where applicable
- label visibility
- optional label field selection

Required figure actions:

- Reset to Default
- Save Draft Style
- Save and Regenerate Figure
- Approve Figure

### Style Override Data Model

Create structured override storage for reviewer figure styling decisions. Overrides are presentation metadata, not source or analysis changes.

Suggested shape:

```text
FigureStyleOverride
  id
  figureId
  projectId
  analysisSnapshotId
  overrides
    - layerId
    - visible
    - zIndex
    - displayName
    - fillColor
    - fillOpacity
    - strokeColor
    - strokeWidth
    - pointSize
    - labelVisible
    - labelField
  createdBy
  createdAt
```

Requirements:

- overrides are sparse
- defaults remain in figure recipes or base styles
- only changed values persist
- overrides are independently auditable
- style changes do not mutate source layers
- style changes do not mutate analysis outputs

### Figure Regeneration Pipeline

Regenerated figures should be produced from:

```text
source data
+ analysis snapshot
+ figure recipe
+ reviewer style overrides
= regenerated figure
```

When a reviewer saves and regenerates a figure:

1. Save the current style override metadata.
2. Create a new figure render job.
3. Render the figure using frozen analysis/source inputs.
4. Apply style overrides during rendering.
5. Store the regenerated output as a new figure version.
6. Make the regenerated figure available for review/export.

Initial output support: PNG.

SVG is preferred if practical. PDF is deferred unless already easy.

### Figure Versioning

Each regeneration produces a new version.

Each figure version should track:

- figure ID
- version number
- created timestamp
- generated by system or reviewer
- style override reference
- output artifact path/reference
- approval state

Version history example:

```text
Figure 4
v1 autogenerated
v2 reviewer hid duplicate hydro layer
v3 reviewer adjusted wetland opacity
approved version: v3
```

Requirements:

- previous versions remain accessible
- approval references a specific version
- approval does not destroy earlier versions
- later edits create new versions
- approved outputs are not silently overwritten

### Figure Approval Workflow

Suggested figure/version states:

- autogenerated
- modified
- regenerated
- approved

Approval requirements:

- approval is tied to an exact figure version
- approved version becomes the export/report target
- later edits create a new version rather than altering the approved version
- approval preserves auditability

### Rendering Architecture

Maintain strict separation between analytical truth and presentation styling.

Reviewer styling changes must never:

- alter geometries
- alter source data
- alter analysis outputs
- alter acreages
- alter intersections
- alter comparison logic
- alter source records
- change determinations

Styling is presentation metadata only.

### Export Integration

Exports should:

- pull the approved figure version by default
- preserve figure numbering
- preserve captions
- preserve legend generation
- preserve report references
- avoid stale autogenerated versions when an approved reviewer version exists

Export priority:

1. Use approved reviewer version if present.
2. Otherwise use latest regenerated version if no approved version exists.
3. Otherwise use autogenerated version.

This hierarchy can be adjusted later, but export behavior must be explicit.

## Recommended Internal Concepts

### Figure Recipe

Defines:

- layer composition
- default styles
- extent
- legend structure
- source layer references
- figure purpose

### Analysis Snapshot

Represents frozen analytical truth used by the figure. It should include or reference:

- source datasets
- selected comparison unit inputs
- analysis results
- generated intersections/metrics
- spatial extent policy

### Style Override Layer

Stores reviewer presentation adjustments. It should be:

- sparse
- auditable
- reversible
- independent from source data

### Render Job

Produces final figure artifacts and references:

- figure ID
- project ID
- analysis snapshot ID
- figure recipe ID
- style override ID
- output format
- render status

## Success Criteria

Sprint 6 is successful when reviewers can:

- open generated figures
- view figure layers
- adjust basic layer styling
- hide/show layers
- reorder layers
- regenerate clean figures
- preserve analytical integrity
- approve final figure versions
- export approved figures into reports

without requiring external GIS software.

## Product Positioning

This feature is a constrained reviewer figure-styling workflow, not a browser GIS platform.

The purpose is to:

- improve readability
- improve communication quality
- support reviewer judgment
- reduce external GIS cleanup work
- preserve reproducibility
- preserve auditability

The purpose is not to replicate ArcGIS or QGIS.

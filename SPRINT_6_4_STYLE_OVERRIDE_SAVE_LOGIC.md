# Sprint 6.4: Style Override Save Logic

## Status

Parked draft for review. Do not implement until the figure editor UI and override model boundaries are accepted.

## Purpose

Implement saving, updating, and resetting sparse reviewer style overrides.

Style overrides are presentation metadata only.

## Requirements

Saving a draft style should:

- validate the target project and figure ID
- validate the analysis snapshot or current figure recipe reference
- store only changed values
- keep defaults in the figure recipe/base style
- preserve prior override audit metadata
- create or update an override record
- record timestamps and actor metadata when available
- avoid mutating generated figure artifacts until regeneration is requested

Reset to default should:

- clear the draft override for the figure or mark it superseded
- leave source data, analysis artifacts, recipes, render jobs, versions, and approval history intact
- make the UI fall back to the autogenerated/base style

## Allowed Override Fields

Per layer:

- `visible`
- `zIndex`
- `displayName`
- `fillColor`
- `fillOpacity`
- `strokeColor`
- `strokeWidth`
- `pointSize`
- `labelVisible`
- `labelField`

Reject unsupported fields instead of silently persisting them.

## Validation Requirements

Validate:

- color values are safe CSS hex values
- opacity values are bounded
- stroke widths are bounded
- point sizes are bounded
- z-index values are bounded integers
- label fields, if supported, are present in allowed/known layer metadata
- layer IDs exist in the figure recipe
- unknown fields are rejected

## Audit Requirements

Override records should include:

- override ID
- project ID
- figure ID
- analysis snapshot ID
- created timestamp
- updated timestamp
- created by / updated by, when available
- sparse layer overrides
- superseded/reset status where applicable

## Tests

Add focused tests for:

- saving sparse overrides
- unchanged defaults are not persisted
- reset clears override state without deleting version history
- invalid colors are rejected
- invalid numeric ranges are rejected
- unknown layer IDs are rejected
- unknown override fields are rejected
- source files and analysis outputs remain byte-identical after save/reset where practical

## Definition Of Done

- Reviewers can save draft style overrides without regenerating.
- Reset to default works without touching analysis or version history.
- Override records are sparse, validated, and auditable.
- Tests prove save/reset does not mutate source or analysis artifacts.

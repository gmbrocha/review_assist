# Sprint 5.5: Reviewer-Supplied Materials And Manual Completion Workflow

## Status

Parked draft for review. Do not implement until Sprint 5.1 through Sprint 5.4 are accepted and the Sprint 5 stabilization checkpoint is accepted.

## Purpose

Build the workflow that lets a reviewer complete report sections/items when the needed source material cannot or should not be generated automatically.

Review Assist must not treat missing, restricted, optional, or manual sources as dead ends. If a report component requires reviewer-supplied text, maps, tables, figures, letters, records, or supporting documents, the app should surface that need clearly and provide a clean way to add/review/export the material.

This is core Sprint 5 work because it connects source policy, report inclusion, human review, and final deliverable assembly.

## Product Principle

The app should reduce the reviewer’s need to crawl through the source warehouse, but the reviewer remains responsible for judgment and for supplying restricted/manual materials when needed.

Automation should identify the gap, explain what is needed, provide the right input surface, preserve provenance, and keep the output review-gated.

## Key Use Cases

### Restricted / Reviewer-Supplied Cultural Records

Examples:
- MDAH archaeology/site-file records
- restricted SHPO/MDAH review materials
- authorized reviewer-supplied cultural resource notes
- public/coarse cultural context used only for POC screening

Expected behavior:
- Public/coarse sources may support POC screening context.
- Restricted cultural records must be clearly marked as reviewer-supplied / authorized-user supplied.
- The app must not imply public/coarse context replaces authorized MDAH/SHPO review.
- The reviewer can upload or enter authorized review material and mark the item complete after review.

### Optional Parcel / Property Context

Examples:
- county parcels
- property age / year-built context
- property ownership or parcel map screenshots
- optional local assessor material

Expected behavior:
- Parcel/property source may remain optional.
- If absent, it should not create an alarming failure.
- If relevant, reviewer can upload a map/table or enter a short summary.
- The report can include the material if reviewed/accepted.

### Manual Attachments

Examples:
- agency consultation letters
- hazardous materials support report
- custom reviewer maps
- project-specific prior-study materials
- PEL/project relationship materials when applicable

Expected behavior:
- Attachment sections should not be generic dead stubs.
- They should clearly state what material is expected.
- Reviewer can upload documents and mark them accepted, not provided, or unable to verify.
- Export should include or reference reviewed materials according to report policy.

### Replacement Figures / Tables / Text

Examples:
- reviewer-created map replacing an autogenerated figure
- edited figure caption
- manually supplied table
- manually written section text

Expected behavior:
- Manual additions become first-class reviewed artifacts.
- They must carry provenance and review status.
- They must be exportable only after review.

## Scope

Implement a clean manual-completion workflow for review items that require or allow reviewer-supplied material.

The workflow should support:

- manual text entry
- replacement figure upload
- caption editing
- manual table upload or table summary
- supporting document upload
- reviewer notes
- accepted / edited / replaced / declined / unable-to-verify states
- export behavior for accepted manual materials

## Non-Goals

Do not implement:
- production authentication
- multi-user permissions
- permanent document management system
- full attachment package redesign
- OCR for uploaded materials unless already available
- automatic interpretation of restricted cultural records
- live MDAH/SHPO access
- broad source acquisition
- PDF export
- advanced audit UI

## Required Concepts

### Manual Completion Mode

Each section/item that can require reviewer input should have a policy such as:

<!-- json
{
  "manual_completion": {
    "allowed": true,
    "reason": "restricted/reviewer-supplied records",
    "accepted_artifact_types": ["text", "figure", "table", "document"],
    "export_behavior": "include_after_review"
  }
}
-->

This can live in the report section policy, source needs manifest, or another canonical policy file if that is already the project convention

## Manual Material Types

Supported material types should include:

- `manual_text`
- `replacement_figure`
- `edited_caption`
- `manual_table`
- `supporting_document`
- `reviewer_note`

## Manual Material Provenance

Every manual/reviewer-supplied artifact should record:

- item ID
- section ID
- material type
- original filename, if uploaded
- stored safe path
- uploaded/created timestamp
- reviewer-supplied flag
- source status: `reviewer_supplied`
- optional reviewer note
- export eligibility
- review status

## Source Status Distinction

The app must distinguish:

- `source_backed_generated`
- `manual_required`
- `reviewer_supplied`
- `restricted_reviewer_supplied_required`
- `optional_absent`
- `not_used`
- `unable_to_verify`
- `deferred_source`

Manual/restricted sources should not appear as failed downloads.

## UI Requirements

### Review Detail Page

The Review Detail page should adapt to the item type.

### Text Section Stub

For manual text sections:

- Show why manual text is needed.
- Show expected content guidance.
- Provide an edit text area.
- Allow reviewer note.
- Allow accept/edit/decline/unable-to-verify.
- Do not show raw debug/source warehouse details by default.

### Figure Stub or Figure Review Item

For figure/manual map items:

- Show current generated/stub state.
- Provide `Edited Caption`.
- Provide `Upload Replacement Figure`.
- Provide `Accept Final`.
- If uploaded figure but no caption edit: use uploaded figure + generated caption.
- If caption edit but no upload: use generated figure + edited caption.
- If both: use uploaded figure + edited caption.

### Table Stub

For manual table items:

- Show expected table purpose.
- Allow table upload if safe format support exists.
- Allow short manual summary if full table upload is not implemented.
- Preserve bounded report behavior.
- Do not dump arbitrary raw rows into the report body.

### Attachment Stub

For manual attachments:

- Show what document/material is expected.
- Allow document upload.
- Allow reviewer note.
- Allow mark accepted / not provided / unable to verify.
- Export reviewed document reference or attachment package entry.

## File Safety Requirements

Uploaded manual materials must:

- Be stored inside the selected project workspace.
- Reject path traversal.
- Reject unsafe filenames.
- Reject unsupported file types.
- Avoid silent overwrite.
- Record stored path in metadata.
- Never expose arbitrary filesystem browsing.
- Never become default raw/audit artifacts.

## Export Requirements

Accepted manual materials should export according to item type:

- Manual text exports as reviewed section text.
- Edited caption exports below figure as normal text.
- Replacement figure exports instead of generated figure.
- Manual table exports as bounded table or referenced attachment.
- Supporting document exports as attachment/reference.
- Reviewer notes remain internal unless policy says otherwise.

Unreviewed manual materials must not bypass the export gate.

## Review Gate Requirements

The export gate should treat manual-required items as incomplete until the reviewer chooses one of:

- `accepted`
- `edited`
- `replaced`
- `declined`
- `unable_to_verify`
- `not_provided`, if supported by policy

Manual-required items should not silently pass as empty stubs.

## Tests

Add or update tests for:

- Manual-required item appears with correct status.
- Restricted/reviewer-supplied cultural item does not appear as failed download.
- Optional parcel source absence is non-alarming.
- Manual text can be saved and reviewed.
- Replacement figure upload is stored safely.
- Edited caption exports instead of generated caption.
- Uploaded figure reuses generated caption when no caption edit exists.
- Uploaded figure + edited caption both export correctly.
- Attachment upload records reviewer-supplied provenance.
- Unsafe filenames/path traversal are rejected.
- Manual material remains review-gated.
- Reviewer notes do not export as report content unless explicitly intended.
- Accepted manual item appears in export package.
- Declined/not-provided manual item does not export as if source-backed.
- Review queue count/target IDs remain stable.
- Compactness tests still pass.

## Documentation Updates

Update the minimum necessary docs:

- `REPORT_ASSEMBLY.md`
- `DATA_SOURCES.md`
- `SOURCE_WAREHOUSE.md`
- `CURRENT_STATE.md`
- `DEFERRED_WORK.md`, if any manual workflow pieces remain deferred

Docs should explain:

- Reviewer-supplied materials are first-class review artifacts.
- Restricted sources are not failed downloads.
- Public/coarse cultural context is distinct from restricted MDAH/SHPO records.
- Optional sources can be absent without blocking report generation.
- Manual materials must still be reviewed before export.

## Definition of Done

Sprint 5.5 is complete when:

- Review Assist can represent manual/reviewer-supplied report items without treating them as broken automation.
- The reviewer has a clear way to supply text, figures, tables, or documents for manual-required items.
- Manual additions preserve provenance and review status.
- Export uses accepted manual materials correctly.
- Missing manual/restricted materials remain honest blockers or reviewer decisions.
- No manual material bypasses the review gate.
- File upload/storage is path-safe.
- The workflow supports MDAH cultural records, parcel/property context, manual attachments, replacement figures, and manual tables/text at least at the policy/workflow level.

## Success Statement

Review Assist should turn a source gap into a clear reviewer action, not a dead stub.

If a section cannot be automated because the source is restricted, optional, manual, or reviewer-supplied, the app should say what is needed, provide a clean place to supply it, preserve the provenance, and keep the human decision in control.
